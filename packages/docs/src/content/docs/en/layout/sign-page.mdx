# Sign Page

The sign page layout gives authentication flows a stable, responsive frame. It uses container queries, so an embedded sign page responds to the space it receives instead of relying on the browser viewport.

## Sign In

Use the aside for brand context and the main region for the focused authentication task. The content slot constrains the form to a comfortable reading width.

## Anatomy

| Class | Role |
|-------|------|
| `.sign-page` | Container-query root and page surface |
| `.sign-page-frame` | Responsive split-page frame |
| `.sign-page-aside` | Supporting brand, illustration, or product context |
| `.sign-page-main` | Primary authentication region |
| `.sign-page-content` | Readable-width form content |

## Accessibility

- Give the page's primary heading an ID and reference it with `aria-labelledby` on the root.
- Use a real `form`, persistent labels, and appropriate `autocomplete` values.
- Keep sign-in and sign-up links descriptive; do not rely on color alone to distinguish them.
- Decorative content in the aside must not interrupt the form's heading and field order.

## Container-aware behavior

The sign page observes its own inline size. A narrow dashboard panel therefore receives the compact stacked layout even when the browser window itself is wide. Avoid viewport breakpoint classes on the five structural slots; let the layout's container queries control their placement.
