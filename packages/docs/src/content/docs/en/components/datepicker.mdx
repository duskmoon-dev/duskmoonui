# Calendar and Datepicker

Calendar is an inline date surface. Datepicker composes an input, trigger and popup.
Both reuse `datepicker.css`; there is no duplicate Calendar stylesheet or mandatory
date runtime. Native date input is the simplest functional path.

## Imports

Individual example prerequisites (including composition and demo actions):

```css
@import "@duskmoon-dev/core/base.css";
@import "@duskmoon-dev/core/themes/sunshine";
@import "@duskmoon-dev/core/components/datepicker.css";
@import "@duskmoon-dev/core/components/form-group.css";
@import "@duskmoon-dev/core/components/button.css";
```

`base.css` supplies global focus/utility definitions and shared spacing/shape tokens;
use your framework reset when appropriate. Substitute the Moonlight theme for dark forms.

Aggregate: `@duskmoon-dev/core`; no-Tailwind: `@duskmoon-dev/core/standalone.css`.
Individual: `@duskmoon-dev/core/components/datepicker.css` plus a theme/reset;
`form-group.css` for field composition. Extensionless `components/datepicker`
exports generated `css` and constructable `styles`.

The browser owns date values, picker interaction, constraints and localized display.
FormData uses the native ISO date value. Do not use the custom
`.datepicker-input-container` wrapper here: it hides the WebKit native picker
indicator for integrations that supply a working custom trigger.

## Datepicker Composition

A custom Datepicker uses `.datepicker`, `.datepicker-input-container`,
`.datepicker-input`, `.datepicker-trigger`, `.datepicker-dropdown` and the
same Calendar classes. A trigger may use native `popovertarget` with a unique
`demo-`-prefixed ID and a popup with `popover="auto"`. Native Popover handles
visibility and light-dismiss, **not** date semantics, calendar focus or positioning.

A non-popover popup uses application-owned `.datepicker-open`,
`.datepicker-dropdown-open` or legacy `.show` state. Closing must also remove hidden
controls from keyboard access, restore appropriate focus and synchronize ARIA.
Do not copy a decorative popup with inert day buttons as a functioning picker.

| Responsibility | Owner |
| --- | --- |
| Colors, grid, today/selected/range/disabled presentation | Core CSS |
| Month length, leap years, parsing, min/max, locale and week start | Application/adapter date engine |
| Selected value and submitted ISO date, clear and reset synchronization | Application/adapter |
| Arrow/Home/End/Page key navigation, roving focus and announcements | Application/adapter |
| Trigger state, focus entering/leaving popup, escape/light-dismiss integration | Application/adapter with native Popover |
| Popup anchor coordinates, overflow/collision and scroll repositioning | Application/adapter |

## Retained Classes And States

`.datepicker-day`, `datepicker-day-today/selected/other-month/disabled`,
`datepicker-day-in-range/range-start/range-end` present adapter state.
Colors: `.datepicker-primary/secondary/tertiary/info/success/warning/error`;
sizes: `datepicker-sm/lg`; `datepicker-ghost` and explicit `datepicker-error` remain.
Use actual `disabled` on an interactive day; a visual disabled class alone cannot
disable keyboard/click behavior. Native inputs follow the
[Validator contract](/duskmoonui/docs/en/components/validator/).

Existing month/year pickers, footer/presets, dual calendars, datetime and date/time
range presentation APIs remain in `datepicker.css`. They require appropriate adapter
behavior and are not completed engines. Full third-party adapters and advanced range
selection are deliberately follow-up work, with no mandatory dependency in Core.
