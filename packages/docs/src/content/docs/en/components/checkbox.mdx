# Checkbox

## Native Contract And Imports

Individual example prerequisites (including composition and demo actions):

```css
@import "@duskmoon-dev/core/base.css";
@import "@duskmoon-dev/core/themes/sunshine";
@import "@duskmoon-dev/core/components/checkbox.css";
@import "@duskmoon-dev/core/components/form-group.css";
@import "@duskmoon-dev/core/components/button.css";
```

`base.css` supplies global focus/utility definitions and shared spacing/shape tokens;
use your framework reset when appropriate. Substitute the Moonlight theme for dark forms.

Aggregate: `@duskmoon-dev/core` with Tailwind v4; no-Tailwind:
`@duskmoon-dev/core/standalone.css`. Individual:
`@duskmoon-dev/core/components/checkbox.css` plus base/theme and
`form-group.css` for associated labels/help. Extensionless `components/checkbox`
exports generated `css` and constructable `styles`, not a behavior runtime.

Use native inputs for values, selection, constraints, submission and reset.
Actual `disabled` or `fieldset disabled` owns semantic disabling.
Use `.validator` for native interaction-based errors and add
`.validator-success` for native success. Explicit `aria-invalid="true"`
wins over those states and color modifiers, including focus.
Supply described error text as well as color. See
[Validator](/duskmoonui/docs/en/components/validator/) and
[Field composition](/duskmoonui/docs/en/components/form-group/).

Checked state and reset are native. Indeterminate is an application-set DOM property,
not an HTML attribute or a submitted third value. Resynchronize it after reset if needed.

Checkboxes allow users to select one or more items from a set or toggle a single option. @duskmoon-dev/core provides a complete set of Material Design 3 checkbox variants with support for checked, indeterminate, and disabled states.

## States

### Indeterminate

The indeterminate (mixed) state represents a partially selected state, commonly used in "select all" scenarios. Set it via JavaScript:

<ComponentShowcase title="Indeterminate Checkbox" code={`<label class="checkbox-label">
  <input type="checkbox" class="checkbox" id="indeterminate-demo" />
  <span>Indeterminate state</span>
</label>

<script>
  document.getElementById('indeterminate-demo').indeterminate = true;
</script>`} />

### Select All Pattern

A common use case for the indeterminate state is "select all" checkboxes:

<ComponentShowcase title="Select All Example" code={`<form class="checkbox-group" id="demo-checkbox-items">
  <label class="checkbox-label">
    <input type="checkbox" class="checkbox" id="demo-checkbox-select-all" />
    <span>Select All</span>
  </label>

  <div class="checkbox-group">
    <label class="checkbox-label">
      <input type="checkbox" class="checkbox" data-demo-item name="item" value="1" checked />
      <span>Item 1</span>
    </label>
    <label class="checkbox-label">
      <input type="checkbox" class="checkbox" data-demo-item name="item" value="2" checked />
      <span>Item 2</span>
    </label>
    <label class="checkbox-label">
      <input type="checkbox" class="checkbox" data-demo-item name="item" value="3" />
      <span>Item 3</span>
    </label>
  </div>
  <button class="btn" type="reset">Reset items</button>
</form>

<script>
  const form = document.getElementById('demo-checkbox-items');
  const selectAll = document.getElementById('demo-checkbox-select-all');
  const items = form.querySelectorAll('[data-demo-item]');

  function updateSelectAll() {
    const checkedCount = [...items].filter(item => item.checked).length;
    selectAll.checked = checkedCount === items.length;
    selectAll.indeterminate = checkedCount > 0 && checkedCount < items.length;
  }

  selectAll.addEventListener('change', () => {
    items.forEach(item => item.checked = selectAll.checked);
  });

  items.forEach(item => item.addEventListener('change', updateSelectAll));
  form.addEventListener('reset', () => requestAnimationFrame(updateSelectAll));
  updateSelectAll();
</script>`} />

The local demo script owns aggregate checked/indeterminate state and reset synchronization.
Only the named item controls are submitted; the select-all control is not another value.

## Best Practices

### Accessibility

- Use semantic `<label>` elements to associate labels with checkboxes
- Provide clear, descriptive labels
- Use `fieldset` and `legend` for checkbox groups
- Ensure sufficient color contrast

### Touch Targets

The checkbox provides adequate touch targets. For mobile-first designs, use larger sizes:

<ComponentShowcase title="Mobile-Friendly Checkbox" code={`<label class="checkbox-label">

## API Reference

### Class Names

| Class | Description |
|-------|-------------|
| `.checkbox` | Base checkbox styling (required, on input element) |
| `.checkbox-xs` | Extra small size (14px) |
| `.checkbox-sm` | Small size (16px) |
| `.checkbox-md` | Medium size (20px, default) |
| `.checkbox-lg` | Large size (24px) |
| `.checkbox-xl` | Extra large size (28px) |
| `.checkbox-primary` | Primary color variant (default) |
| `.checkbox-secondary` | Secondary color variant |
| `.checkbox-tertiary` | Tertiary color variant |
| `.checkbox-success` | Success color variant |
| `.checkbox-warning` | Warning color variant |
| `.checkbox-error` | Error color variant |
| `.checkbox-info` | Info color variant |
| `.checkbox-label` | Label wrapper for checkbox + text |
| `.checkbox-group` | Container for vertical checkbox group |
| `.checkbox-group-horizontal` | Horizontal layout modifier |
| `.checkbox-group-label` | Group label text |

### HTML Structure

Simple checkbox:
```html
<input type="checkbox" class="checkbox" aria-label="Example checkbox" />
```

With label:
```html
<label class="checkbox-label">
  <input type="checkbox" class="checkbox" />
  <span>Label text</span>
</label>
```

### States

| State | How to Apply |
|-------|--------------|
| Checked | `checked` attribute |
| Disabled | `disabled` attribute |
| Indeterminate | `element.indeterminate = true` (JavaScript) |
| Focus | Automatic via `:focus-visible` |
