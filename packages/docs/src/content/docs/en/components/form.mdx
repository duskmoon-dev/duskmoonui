# Form

Compose native controls. Core styles appearance and state; the browser owns values,
selection, constraints, submission and reset. Applications own remote validation and
asynchronous work. The legacy `form.css` entry imports canonical controls and composition
rather than maintaining competing implementations.

## Imports

Individual example prerequisites (including composition and demo actions):

```css
@import "@duskmoon-dev/core/base.css";
@import "@duskmoon-dev/core/themes/sunshine";
@import "@duskmoon-dev/core/components/form.css";
@import "@duskmoon-dev/core/components/switch.css";
@import "@duskmoon-dev/core/components/button.css";
```

`base.css` supplies global focus/utility definitions and shared spacing/shape tokens;
use your framework reset when appropriate. Substitute the Moonlight theme for dark forms.

Aggregate: `@duskmoon-dev/core` with Tailwind v4. No-Tailwind: `@duskmoon-dev/core/standalone.css`.
Individual: `@duskmoon-dev/core/components/form.css` plus theme/reset; this includes
Input, File Input, Checkbox, Radio, legacy Toggle, Select, Textarea, Range and Form Group.
Add `rating.css`, `otp-input.css`, `switch.css`, `datepicker.css` or
`filter-group.css` only when needed. Extensionless imports export generated
`css` and `styles`. The regular `/plugin` provides tokens/utilities, not component CSS;
the generated standalone plugin also includes components.

A server/application can read `new FormData(form)`. Checked checkboxes contribute their
value; unchecked and disabled controls contribute none. Reset restores HTML defaults,
not application async state. Do not add a stale decorative fill or static value ARIA to Range.

## Compatibility And Semantics

`.form-control`, `.label`, `.label-text`, `.label-text-alt`,
`.helper-text.error/success/warning/info`, wrapper color/error states and legacy
`.toggle` remain available. Prefer `.form-group` + associated `.form-label` +
native control + described helper/error text for new fields.
`.form-group-disabled` is legacy visual styling, not semantic disabling:
use `fieldset disabled`. Place `required` on the actual control.
Automatic native colors now require the explicit
[Validator API](/duskmoonui/docs/en/components/validator/);
`.validate` retains immediate native validity presentation.
