# File Upload

For basic file selection use [native File Input](/duskmoonui/docs/en/components/file-input/).
File Upload provides richer dropzone, list, preview and progress **presentation**.
CSS does not implement drag/drop, previews, file validation or upload transport.

## Imports

Individual example prerequisites (including composition and demo actions):

```css
@import "@duskmoon-dev/core/base.css";
@import "@duskmoon-dev/core/themes/sunshine";
@import "@duskmoon-dev/core/components/file-upload.css";
@import "@duskmoon-dev/core/components/file-input.css";
@import "@duskmoon-dev/core/components/form-group.css";
@import "@duskmoon-dev/core/components/button.css";
```

`base.css` supplies global focus/utility definitions and shared spacing/shape tokens;
use your framework reset when appropriate. Substitute the Moonlight theme for dark forms.

Aggregate: `@duskmoon-dev/core`; no-Tailwind: `@duskmoon-dev/core/standalone.css`.
Individual: `@duskmoon-dev/core/components/file-upload.css` plus theme/reset.
Extensionless `components/file-upload` exports generated `css` and `styles`.
Use `file-input.css` for the native input in this example and `form-group.css`
for its label/help.

## Operable Native Input Inside The Surface

This example opens the native file picker; it does not promise drag/drop or upload.
The input is deliberately visible and focusable instead of a zero-sized hidden target.

<ComponentShowcase title="File selection surface" code={`<form enctype="multipart/form-data">
  <div class="file-upload">
    <div class="file-upload-dropzone">
      <label class="form-label" for="demo-upload-native">Select attachments</label>
      <input id="demo-upload-native" name="attachments" type="file" class="file-input" multiple aria-describedby="demo-upload-help">
      <p id="demo-upload-help" class="file-upload-subtitle">Selected files remain local until an application uploads them.</p>
    </div>
  </div>
  <button type="reset" class="btn">Clear selected files</button>
</form>`} />

## Progress Styling Sample

This fixed-state sample is non-interactive and does not claim upload activity:

<ComponentShowcase title="Upload status styling only" code={`<div class="file-upload" role="img" aria-label="Upload presentation sample, report.pdf at 50 percent">
  <div class="file-upload-list" aria-hidden="true">
    <div class="file-upload-item uploading">
      <div class="file-upload-item-info">
        <span class="file-upload-item-name">report.pdf</span>
        <span class="file-upload-item-size">240 KB</span>
        <div class="file-upload-progress"><div class="file-upload-progress-bar" style="width:50%"></div></div>
      </div>
    </div>
  </div>
</div>`} />

In an application, give progress truthful values and suitable announcements. Implement
file removal using a real labeled button, and synchronize it with the submission source.
Reset must clear native files, generated object URLs, previews, progress and application
queues. Native reset alone does not clear those additional states.

## Retained APIs And Ownership

`.file-upload`, `file-upload-dropzone`, `file-upload-input` (legacy hidden input),
`file-upload-icon/text/title/subtitle/browse`, `file-upload-list/item`,
`file-upload-item-icon/info/name/size/remove`, `file-upload-progress/bar`,
`file-upload-preview/item/image/remove`, `file-upload-button` and
`file-upload-compact` remain supported. Color variants are primary/secondary/tertiary/
info/success/warning/error/accent/neutral/base.

Legacy `.dragging`, `.disabled`, `.uploading`, `.success`, `.error` classes
present state supplied by an application. A disabled surface class does not disable
native descendants; use actual `disabled` or `fieldset disabled`.
Applications own drag events, dropped files, file-size/content validation, object-URL
lifecycles, transport, cancellation, progress and accessible announcements.
