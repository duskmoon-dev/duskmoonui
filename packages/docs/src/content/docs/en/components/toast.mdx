# Toast

Toasts provide brief, non-blocking feedback about an application process. In DuskMoonUI, `.toast-container` owns fixed positioning and stacking while `.toast` is the individual notification. This meaning is intentionally different from daisyUI and remains backward compatible.

For static HTML, make the container a manual popover and connect buttons with native `command` and `commandfor`. The browser owns open/closed rendering; DuskMoonUI supplies presentation only. Timers, queues, action execution, request state, and auto-dismiss policy remain consumer-owned.

## Basic Usage

Every example on this page starts closed and is opened by a button click.

<ComponentShowcase title="Basic Toast" code={`<button type="button" class="btn btn-primary"
  command="show-popover" commandfor="demo-toast-basic">
  Show toast
</button>

<div id="demo-toast-basic"
  class="toast-container toast-container-top-end"
  popover="manual">
  <div class="toast" role="status" aria-live="polite">
    <div class="toast-content">
      <div class="toast-message">This is a simple toast notification</div>
    </div>
    <button type="button" class="toast-close" aria-label="Dismiss notification"
      command="hide-popover" commandfor="demo-toast-basic">×</button>
  </div>
</div>`} />

`popover="manual"` avoids unrelated outside clicks dismissing a notification. Always provide an explicit close command, or use `command="toggle-popover"` on the trigger when the same control should both open and close it.

## Accessibility and Lifecycle

- Use `role="status"` or `aria-live="polite"` for ordinary confirmations and background updates.
- Reserve `role="alert"` for urgent failures that require immediate attention.
- Give every close button an accessible name.
- Showing a pre-rendered live region may vary by assistive technology. For critical application flows, insert or update the message when the event occurs and test with the supported screen readers.
- Native popover commands control visibility only. They do not manage queues, timers, asynchronous state, or action execution.
- When using the legacy class API, remove closed notifications from the DOM or apply `hidden`/`inert`; opacity and transforms alone are not complete dismissal.
- Command Invokers require browser support for `command` and `commandfor`. Consumers supporting older browsers can call `showPopover()`/`hidePopover()` from an explicit adapter without changing the markup structure.

## Legacy Open-State API

Existing `.toast-open`, `.show`, and `.toast-show` classes remain supported for framework-managed state. Native command examples do not need these classes because `.toast-container[popover]:popover-open` supplies the visible state.

```html
<div class="toast-container toast-container-top-end">
  <div class="toast toast-show" role="status">Framework-managed notification</div>
</div>
```

## API Reference

### Native Attributes

| Attribute | Element | Purpose |
|---|---|---|
| `popover="manual"` | `.toast-container` | Keeps the fixed notification surface closed until invoked |
| `command="show-popover"` | Trigger button | Opens the target container |
| `command="hide-popover"` | Close or action button | Closes the target container |
| `commandfor="demo-toast-*"` | Button | References the unique container ID |

### Container Classes

| Class | Description |
|---|---|
| `.toast-container` | Fixed positioning and stacking container |
| `.toast-container-top-right`, `.toast-container-top-left` | Preserved physical positioning |
| `.toast-container-bottom-right`, `.toast-container-bottom-left` | Preserved physical positioning |
| `.toast-container-top-start`, `.toast-container-top-end` | RTL-aware top positioning |
| `.toast-container-bottom-start`, `.toast-container-bottom-end` | RTL-aware bottom positioning |
| `.toast-container-top-center`, `.toast-container-bottom-center` | Center positioning |
| `.toast-container-stacked` | Layered presentation for multiple notifications |

### Toast Classes

| Class | Description |
|---|---|
| `.toast` | Individual notification item |
| `.toast-open`, `.show`, `.toast-show` | Preserved framework-managed visible states |
| `.toast-primary`, `.toast-secondary`, `.toast-tertiary` | DuskMoon brand colors |
| `.toast-info`, `.toast-success`, `.toast-warning`, `.toast-error` | Semantic colors |
| `.toast-filled`, `.toast-ghost` | Surface variants |
| `.toast-sm`, `.toast-lg`, `.toast-compact` | Size and density variants |
| `.toast-accent` | Logical-start accent edge |
